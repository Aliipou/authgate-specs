# Security Policy

## Reporting a vulnerability

Please do not open a public issue. Report privately through GitHub's
"Report a vulnerability" (Security tab), including a reproduction if you have one.

You should get an acknowledgement within a few days. This is a research and
engineering project maintained by one person, so please assume good faith about
timelines rather than urgency guarantees.

## Scope and honest status

This repository is **research/engineering software**. It has not been through an
external security audit, and it should not be relied on as the sole control
protecting anything valuable. Where a component makes a security claim, the
evidence for that claim is in the repository — tests, proofs, or a threat model —
and where evidence is absent the claim should be read as aspirational.

Findings that demonstrate a claimed invariant does not hold are especially welcome,
and will be recorded in the repository rather than quietly fixed.
